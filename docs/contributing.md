# Contributing

## Branches

Work on a branch named after its purpose, then open a pull request on `main`.
The branches already in the repository use these prefixes:

| Prefix | For |
|---|---|
| `feat/...` | a new feature |
| `fix/...` | a bug fix |
| `build/...` | build system and tooling |
| `chore/...` | maintenance |

## Commits

Short messages in English, starting with a type: `feat: ...`, `fix: ...`,
`docs: ...`, `chore: ...`. One commit does one thing.

## Pull requests

The template (`.github/pull_request_template.md`) asks for:

- `Closes #<issue>`
- **Changes**: what was done
- **How to test**: how a reviewer can check it

Do not edit the code of another part without telling its owner: `engine/core`,
the server, the client and the game logic each have an owner.

## Continuous integration

`.github/workflows/ci.yml` runs on every push to `main` and on every pull
request:

- **Build and test (Linux)**: `linux-debug` preset, then `ctest`.
- **Build and test (Windows)**: `windows-debug` preset, then `ctest`.
- **Documentation**: `mkdocs build --strict`, so a broken link fails the check.

The same workflow runs on the mirror repository
(`leroy-antoine/rtype`). There, once the three jobs pass on a push, a fourth
job pushes the same branch to the official repository. It needs the secret
`OFFICIAL_TOKEN` (a personal access token that can write the contents of the
official repository). The push is never forced: a branch that diverged on the
official side is not overwritten.

The vcpkg binary cache is kept between runs, so only the first run builds the
dependencies from source. Run the same commands locally (see
[Build and run](build.md)) before opening a pull request.

## Coding conventions

Written for the game logic and recommended for new code elsewhere:

- lines of **80 columns** at most;
- functions of **20 lines** at most, **5 parameters** at most, **2 nested
  conditions** at most;
- no ternary operator;
- data in `struct`s, behaviour in functions, constants in a config header;
- `#pragma once` as include guard;
- private members prefixed with `_`.

More details and the reasoning:
[game logic conventions](game-logic.md#coding-conventions).

## Documentation

When you add a feature, update the documentation of its part in the same pull
request: the tick table or status list for the game logic, the open questions
for the server and the client, the [protocol page](protocol.md) for anything
that changes what goes on the network.

When you add a monster, a boss, a zone or an obstacle, also add its name for
the maps written by the players (`Names.hpp` and `ObstacleParser.cpp` of
`rtype::mapjson`) and in [the guide](custom-maps.md); see
[custom maps for developers](custom-maps-internals.md#how-to).

## Documentation website

The documentation is also a website, generated by
[MkDocs](https://www.mkdocs.org/) (Material theme) from the `docs` folder and
the file `mkdocs.yml` at the root. Every page is a Markdown file of `docs`; the
menu is the `nav` part of `mkdocs.yml`: a new page must be added there.

Install the tools once, in a virtual environment (nothing is installed on the
system):

```
python3 -m venv .venv-docs
.venv-docs/bin/pip install -r requirements-docs.txt
. .venv-docs/bin/activate
```

Then:

| Command | Does |
|---|---|
| `mkdocs serve` | shows the website on `http://127.0.0.1:8000`, reloaded at each save |
| `mkdocs build --strict` | builds it in `site/`; a broken link or anchor fails the build |

Rules for a page:

- link to other pages with a relative link (`protocol.md#error-handling`), and
  never to a file outside `docs` (write the path of a source file in code:
  `` `src/server/game/App.cpp` ``);
- give a text alternative to every image, keep the titles in order (one `#`,
  then `##`, `###`), and never rely on a color alone to say something;
- the documentation is written in English.

**Publishing.** The website is served from a separate public repository
(`rtype-doc`), cloned next to this one as `../DOC_RTYPE`. This repository stays
private: only the generated website goes to the public one.

```
scripts/publish-docs.sh
cd ../DOC_RTYPE && git add -A && git commit -m "docs: update" && git push
```

In the settings of the public repository, **Pages** must serve the branch
`main`, folder `/ (root)`. The website is then at
<https://leroy-antoine.github.io/rtype-doc/>.
